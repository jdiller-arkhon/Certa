# Security review — Phase 2 and additions (October 2026)

Scope: everything from commit `082d3b8` to the commit that adds this file. This covers the fleet API, flights, offline outbox, expiry alerts, inspector share links, Argus API keys and verification, conditions lookups, Web Push, and 3D model uploads.

Method: an independent adversarial review traced code paths and probed a throwaway database. The probes included a real pilot-role member, cross-org references, and forged headers. Every confirmed finding below has a fix and a regression test in `apps/api/test/security.test.ts`, unless noted otherwise.

**Result:** no critical or high-severity issues. Tenant isolation (row-level security on every new route) and role checks held under the probes.

## Confirmed findings: all fixed

| # | Severity | Finding | Fix |
|---|---|---|---|
| M1 | Medium | Share-link tokens appeared in API request logs (in the URL). | The request log serializer replaces `/public/share/<token>` with `:token`. |
| M2 | Medium | Rate limits could be bypassed by forging `X-Forwarded-For` (`trustProxy: true`). The verify limiter was keyed on the raw bearer string. | Only the configured hop count is trusted (`TRUST_PROXY_HOPS`, Caddy = 1). The verify limiter keys on the parsed key prefix, or on the IP when the key is malformed. |
| M3 | Medium | A pilot could store a fabricated pre-flight go/no-go on a flight. | The server recomputes and stores its own check when it stores the flight. The client's copy is ignored. |
| L1 | Low–med | A shared browser kept receiving the previous user's push alerts after sign-out. | Sign-out removes this browser's subscription in every org, then unsubscribes it. |
| L2 | Low | Any org member who knew another member's push endpoint could cancel their subscription. | Taking over another member's row requires the same browser keys. Otherwise the server returns 409. |
| L3 | Low | Share-token hashes and push keys/endpoints were copied into audit before/after images. | Migration `0005_audit_redaction` adds them to the redaction list. Rows written before the migration remain, because the log is append-only. |
| L4 | Low | A blank verify lookup (`certificateNumber=-`) matched the first record with an empty field. | Blank lookups return 400. |
| L5 | Low | A duplicate battery in one flight caused a 500, which stalled the offline outbox. | Zod rejects duplicates with 400. |
| L6 | Low | Flight edits skipped the 24-hour duration cap. | The cap is enforced on PATCH too. |
| L7 | Low | Control characters U+0080–U+009F in a record crashed the PDF packet. | They are replaced before rendering. |
| — | Correctness | Re-sending a deleted flight's id returned 404. Replaying another pilot's flight id returned that flight. | Both now return 409 with a clear message. |

## Hardening applied

- Push notification clicks open only same-origin, in-scope paths. URLs with backslashes are rejected.
- Conditions lookups follow only `https://api.weather.gov/…` URLs and well-formed station ids.
- Request ids are always generated by the server. Clients can no longer choose the id written to the audit log.
- Share-link lists require `exports.create`. Pilots see only links to their own packet.
- Offline cached records are cleared when a different user signs in on the device.

## Open for the owner's decision (not changed)

- Model uploads (up to 20 MB) are buffered before the auth check runs. Abuse is bounded by the body limit. Moving the auth check into an `onRequest` hook would refuse unauthenticated bodies earlier.
- `aircraft.override_grounding` is defined but unused. Return-to-service needs `aircraft.ground` (chief pilot, maintenance tech). PATCH can retire or un-retire an aircraft. Confirm the intended policy.
- Conditions results are cached per ~1 km cell for 10 minutes. Near an airspace boundary, a neighbour's result can be reused.
- None of this has had external penetration testing. The 19 FAA rule values still need verification by a qualified person (see `docs/RULES_VERIFICATION.md`).
